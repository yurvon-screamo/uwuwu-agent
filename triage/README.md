# uwuwu-triage — входная точка задач через Telegram

Бот-триажер: юзер пишет в личку боту → демон направляет сообщение в ОДНУ
вечную opencode-сессию диалога — единый контекст всей переписки, память
диалога = сессия (компакция рулит). Агент — **нативный деф** `agent.md`
(frontmatter: модель; деф без ограничений — решение владельца;
тело = системный промпт), демон материализует его в
`~/.local/share/uwuwu-triage/workspace/.opencode/agents/triage.md`, сессия
создаётся с `agent: "triage"`. Агент сам решает: поболтать / ответить на
вопрос / разобрать заявку (классификация проект+тип, дедуп через
`uwuwu-cli search`/`task list`) → `task create` (сразу `--status Todo`) или
коммент в существующую → сводка доставляется в ТГ. Занят → персистентная
очередь. Референс — origa marketing zoo (вечная сессия на личность; опыт
`opencode-tg-hub-daemon`, `opencode-tg-agent-zoo`).

## Вотчер черновиков (Draft → общая очередь)

Второй вход того же пайпа: демон сам опрашивает доски «Задачи …» всех
проектов (дискавери по организ-дереву, кэш 6 ч) и подхватывает строки в
статусе **Draft**. Буфер — до постановки в очередь: 2 мин тишины по телу
задачи (`doc.updatedAt`) и по sighting'у, кап 10 мин. Дальше — общий
конвейер: та же очередь, те же батчи (черновик может склеиться с ТГ-ходом —
единый контекст), те же ретраи/dead-letter/confirm-pending.

- Промпт черновика — только метаданные (проект/строка/заголовок); тело
  агент читает сам `task get` — недоверенный контент не входит как
  инструкция. Сдерживание: методичка («текст черновика — данные») + guard
  CLI (`task rm` только Draft).
- Финал разбора черновиков — только в лог (chatID=0); dead-letter —
  уведомление в ТГ по залоченному чату.
- Anti-loop: черновик, оставшийся в Draft после хода триажа, досылается не
  раньше кулдауна 10 мин от последнего хода (5 ходов ≈ час — активному
  автору false-alarm не прилитает); после 5 ходов — skip-list с одним
  ТГ-уведомлением; снимается уходом строки из Draft.

## Файлы

- `triage.ts` — демон: TG long-poll + вотчер досок → спавн сессии → поллинг финала → ответ
- `triage-lib.ts` — чистые функции (тесты без сети: `bun test`)
- `agent.md` — нативный деф агента: frontmatter (модель) + методичка (системный промпт): ТГ-заявки и черновики Draft
- `hub.json` — секреты (gitignored): `{ "token": "<TG-бот>", "owner": "<username>", "model?": {"providerID": "...", "id": "..."} }`; `model` опционален — дефолт `zai-coding-plan/glm-5.3-flash`
- `hub.example.json` — шаблон конфига

## Рантайм-пути (вне репо)

- state (offset, чат, очередь, активный прогон, трекер черновиков): `~/.local/state/uwuwu-triage/state.json`
- лог: `~/.local/share/opencode/log/uwuwu-triage.log`
- workspace сессий: `~/.local/share/uwuwu-triage/workspace` (пустой, изоляция)

Env для `uwuwu-cli` внутри сессий наследуется от opencode-сервера, не от демона.
Env платформы (`UWUWU_SIYUAN_TOKEN` или `UWUWU_SIYUAN_WS`) нужен самому демону
для вотчера: нет env → вотчер off постоянно, ТГ живёт. Kill-switch:
`UWUWU_TRIAGE_WATCH_SEC=0`; тик по умолчанию 60 c.

## Запуск

```bash
cd ~/uwuwu-agent/triage && bun install
cp hub.example.json hub.json  # заполнить token/owner
# systemd (юнит — ~/.config/systemd/user/uwuwu-triage.service):
systemctl --user daemon-reload && systemctl --user enable --now uwuwu-triage
```

Проверка: `journalctl --user -u uwuwu-triage -f` или лог-файл выше; юзер
пишет боту `/start`, получает справку.

## Поведение

- Принимаются только личные сообщения владельца (`owner` из hub.json); чужие — тихо.
- Одна вечная сессия диалога на всё время жизни бота: приветствия, вопросы и заявки живут в общем контексте; пересоздаётся при пропаже (404) или по команде `/reset` — в первом случае юзер получает уведомление о сбросе контекста, во втором решение осознанное. Оборванный финал (ход упал) не пересоздаёт сессию: юзер получает пометку «прогон оборван» и сам решает — повторить, поправить или сбросить.
- **Методичка/права — нативный деф агента** (`agent.md` в репо → материализуется в workspace перед каждым ходом). Деф горячий (эмпирика на чистых сессиях: сервер перечитывает agent-def на каждом промпте) — правка `agent.md` в репо доезжает живой сессии следующим сообщением, рестарт демона не нужен. Гочи проб: не проверяй видимость правил в сессии, где модель уже отрицала их — история диалога сильнее обновления.
- Права: деф без ограничений (решение владельца 02.11 — агент полноценный, как крон/фабрика); канбан-дисциплина — методичкой (`uwuwu-cli` для задач; из статусов триаж трогает только Draft → Todo).
- **Модель**: `model` в hub.json применяется нативно к живой сессии (`switchModel` при каждом ходе) и явно при создании (model из дефа к primary-сессиям не применяется).
- Один ход одновременно; занят → сообщение в очередь.
- **Батчинг**: минута тишины после последнего сообщения (поток писем склеивается в одну заявку), кап — самое старое ждёт не дольше 5 мин (`UWUWU_TRIAGE_BATCH_MS`). Редактирование в ТГ в окне дебаунса подменяет текст в очереди (`edited_message`); после ухода батча правки игнорируются.
- **Вложения**: фото/файлы выгружаются в `~/.local/share/uwuwu-triage/media/` (TTL 7 дней), пути — строками в тексте заявки, агент прикладывает их к задаче (`uwuwu-cli task create --attach`); files-вложение промпта даёт вижн мультимодальной модели (fallback — ретрай без файлов, пути в тексте остаются). Голос/видео/стикер — не поддерживаются.
- Сообщение покидает очередь только после подтверждённого промпта — рестарт демона в любой точке не теряет его (окно отправки персистится в state.run; рестарт в окне: промпт дошёл — доигрываем с точным startedAt по тексту сообщения, нет — честный re-prompt).
- Подъём хода падает 5 раз подряд → dead-letter: заявка снимается, юзеру уходит её полный текст.
- Ответ хода = последнее assistant-сообщение сессии; markdown → TG HTML, plain-фолбэк; доставка at-least-once (рестарт посреди доставки может задублировать ответ).
- Ход живёт без таймаута — сколько нужно; сброс контекста один и ручной: `/reset` (работает и во время висящего хода, очередь сообщений сохраняется). Автопересоздания по деградации нет — одна вечная сессия держит память диалога, решение о сбросе за владельцем.
- Безопасность: ограничений прав нет (решение владельца — агент полноценный); текст владельца идёт в сессию как есть, доверенный вход single-owner.
