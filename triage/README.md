# uwuwu-triage — входная точка задач через Telegram

Бот-триажер: юзер пишет в личку боту → демон направляет сообщение в ОДНУ
вечную opencode-сессию диалога — единый контекст всей переписки, память
диалога = сессия (компакция рулит). Агент — **нативный деф** `agent.md`
(frontmatter: модель + permissions `bash: только uwuwu-cli`, `edit: deny`;
тело = системный промпт), демон материализует его в
`~/.local/share/uwuwu-triage/workspace/.opencode/agents/triage.md`, сессия
создаётся с `agent: "triage"`. Агент сам решает: поболтать / ответить на
вопрос / разобрать заявку (классификация проект+тип, дедуп через
`uwuwu-cli search`/`task list`) → `task create` или коммент в существующую →
сводка доставляется в ТГ. Занят → персистентная очередь. Референс — origa
marketing zoo (вечная сессия на личность; опыт `opencode-tg-hub-daemon`,
`opencode-tg-agent-zoo`).

## Файлы

- `triage.ts` — демон: TG long-poll → спавн сессии → поллинг финала → ответ
- `triage-lib.ts` — чистые функции (тесты без сети: `bun test`)
- `agent.md` — нативный деф агента: frontmatter (модель, permissions: bash только `uwuwu-cli *`, edit deny) + методичка (системный промпт)
- `hub.json` — секреты (gitignored): `{ "token": "<TG-бот>", "owner": "<username>", "model?": {"providerID": "...", "id": "..."} }`; `model` опционален — дефолт `zai-coding-plan/glm-5.3-flash`
- `hub.example.json` — шаблон конфига

## Рантайм-пути (вне репо)

- state (offset, чат, очередь, активный прогон): `~/.local/state/uwuwu-triage/state.json`
- лог: `~/.local/share/opencode/log/uwuwu-triage.log`
- workspace сессий: `~/.local/share/uwuwu-triage/workspace` (пустой, изоляция)

Env для `uwuwu-cli` внутри сессий наследуется от opencode-сервера, не от демона.

## Запуск

```bash
cd ~/uwuwu-agent/triage && bun install
cp hub.example.json hub.json  # заполнить token/owner
# systemd (юнит — ~/.config/systemd/user/uwuwu-triage.service):
systemctl --user daemon-reload && systemctl --user enable --now uwuwu-triage
```

Проверка: `journalctl --user -u uwuwu-triage -f` или лог-файл выше; юзер
пишет боту `/start`, получает справку.

## Поведение

- Принимаются только личные сообщения владельца (`owner` из hub.json); чужие — тихо.
- Одна вечная сессия диалога на всё время жизни бота: приветствия, вопросы и заявки живут в общем контексте; пересоздаётся при пропаже (404), после 3 оборванных финалов подряд (деградация) или по команде `/reset` — в первых двух случаях юзер получает уведомление о сбросе контекста, в третьем решение осознанное.
- **Методичка/права — нативный деф агента** (`agent.md` в репо → материализуется в workspace). Системный промпт сессии снапшотится на создании (эмпирика opencode 2.2.5: AGENTS.md, `switchAgent` и экспериментальные instructions-entries живую сессию не меняют — модель трактирует их как пользовательский контент). Правка дефа → применится к новой сессии; демон замечает рассинхрон и предлагает владельцу `/reset` (контекст теряется — решение за владельцем).
- **Модель**: `model` в hub.json применяется нативно к живой сессии (`switchModel` при каждом ходе) и явно при создании (model из дефа к primary-сессиям не применяется).
- Один ход одновременно; занят → сообщение в очередь (персистится, рестарт не теряет, порядок сохраняется).
- Сообщение покидает очередь только после подтверждённого промпта — рестарт демона в любой точке не теряет его (окно отправки персистится в state.run; рестарт в окне: промпт дошёл — доигрываем с точным startedAt по тексту сообщения, нет — честный re-prompt).
- Подъём хода падает 5 раз подряд → dead-letter: заявка снимается, юзеру уходит её полный текст.
- Ответ хода = последнее assistant-сообщение сессии; markdown → TG HTML, plain-фолбэк; доставка at-least-once (рестарт посреди доставки может задублировать ответ).
- Ход > 15 мин → юзеру предупреждение, наблюдение отпускается.
- Деградация: 3 оборванных финала подряд → пересоздание сессии; пересоздания чаще раза в 30 мин → пауза обработки на 30 мин (circuit breaker, сообщение владельцу).
- Безопасность: инструментальная — нативные permissions дефа (bash: только `uwuwu-cli *`, edit: deny). Текст владельца идёт в сессию как есть (единый диалог, без маркеров) — осознанный трейд-оф.
