# uwuwu-lead — ночной аудитор платформы uwuwu

Агент-демон «Lead»: раз в сутки ночью (04:30 по локалке) аудитирует доски
всех проектов и сессии суток — зависшие агенты и статусы, техдолг (заводит
задачи Draft'ами через пайп триажа), отклонения от целей (`uwuwu-cli goal`),
повторяющиеся инциденты — и шлёт сводку в ТГ-личку. Тихие сутки — молчание.
Юзер может обращаться к нему вручную в любой момент: тот же ТГ-бот, та же
вечная сессия.

Механика — универсальное ядро демона (`lib/hub.ts`, общее с триажем):
ТГ long-poll + ночной шедулер (источник промптов) → ОДНА вечная opencode-сессия
(мастер-сессия: постоянный контекст аудитов, компакция рулит) → инкрементальная
доставка ответов в ТГ. Агент — нативный деф `lead-agent.md` (frontmatter:
модель; тело = системный промпт), демон материализует его в
workspace/.opencode/agents/. Крон-контур uwuwu-cron сознательно не
используется — тот спавнит отдельную сессию на ран-карточку, что убило бы
постоянный контекст аудитов.

Зоны соседей (не дублируются): дример пост-обрабатывает каждую уснувшую
сессию (опыт в вики) — Lead работает суточной картиной и кросс-проектными
выводами; фабрика сигналит на 30-минутные застои per-task; триаж валидирует
черновики. Данные для аудита агент собирает сам штатными инструментами:
`uwuwu-cli` (task/goal/doctor/kernel sql) и `tools/opencode_audit.py`
(opencode.db) — нового кода данных демон не несёт.

## Тайм-аут тишины выходного потока

Общий контур с триажем (ядро `lib/hub.ts`, правило опыта «SiYuan-контур
uwuwu», Режим 5 дополнение): метка `lastDeliveryAt` обновляется успешной
доставкой в ТГ и завершённым финалом хода — тихий аудит (молчание легитимно,
`allowSilent`) тоже выход: финал хода состоялся. Луп тишины при
`LEAD_SILENCE_TIMEOUT_MS` (26 ч: гэп между финалами ночного аудита ~24 ч
плюс запас на продолжительность хода и сдвиг слота) алертит в лог и ТГ;
недоставленный алерт ретраится раз в час. Инвариант: луп не делает
kernel/MCP-вызовов — детектор переживает деградацию ядра. Критерий
пересмотра порога: первый ложняк после выката (ход аудита длиннее запаса) —
порог вверх.

## Файлы

- `lead.ts` — вход: профиль демона + ночной шедулер (источник промптов)
- `lead-lib.ts` — чистые функции шедулера (тесты: `bun test`)
- `lead-agent.md` — нативный деф агента: методичка аудита (п.1–6 постановки)
- `hub.example.json` — шаблон конфига; `hub.json` — секреты (gitignored):
  `{ "token": "<TG-бот>", "owner": "<username>", "model?": {...} }`; `model`
  опционален — дефолт `zai-coding-plan/glm-5.3` вариант `max` (ночь не
  торопится, аудит — аналитика пачкой)

## Рантайм-пути (вне репо)

- state (offset, чат, очередь, ход, `cron.lastFireDate`): `~/.local/state/uwuwu-lead/state.json`
- лог: `~/.local/share/opencode/log/uwuwu-lead.log`
- workspace сессий: `~/.local/share/uwuwu-lead/workspace` (изоляция)

Env-крюки (тестовые, в systemd-юнит не задаются): `UWUWU_LEAD_HOME` — корень
state/воркспейса/лога/медиа (дефолт — homedir); `UWUWU_LEAD_TG_API` — база
TG-API (дефолт — api.telegram.org, mock-TG для досмерджевого протокола);
`UWUWU_LEAD_E2E=1` — сессии с префиксом `[e2e]` (дример их пропускает,
конвенция lib/e2e-tag.ts); `UWUWU_LEAD_AUDIT_AT="HH:MM"` — время аудита
(дефолт 04:30); `UWUWU_LEAD_BATCH_MS` / `UWUWU_LEAD_POLL_SEC` — дебаунс
батча и тик поллинга.

## Запуск

```bash
cd ~/uwuwu-agent/lead && bun install
cp hub.example.json hub.json  # token бота Lead, owner
# systemd (юнит — ~/.config/systemd/user/uwuwu-lead.service):
systemctl --user daemon-reload && systemctl --user enable --now uwuwu-lead
```

**Первичный `/start` — обязательный шаг развёртывания**: до первого
сообщения владельца `chatID` не залочен и ночные сводные уходят только в
лог (`state.json` → `chatID`). Напиши боту Lead `/start` сразу после старта
юнита. Слоты, пропущенные из-за лежавшего демона, доезжают догоном при
старте (аудит идемпотентен, повторная сводка дешевле тишины).

Проверка живости: `journalctl --user -u uwuwu-lead -f` или лог-файл выше;
в строке старта — бот, owner, chat, model (`glm-5.3#max`).

## Поведение

- Принимаются только личные сообщения владельца (`owner` из hub.json); чужие — тихо.
- Одна вечная сессия: ночные аудиты и ручной диалог — общий контекст;
  пересоздаётся при пропаже (404) или по `/reset`.
- Ночной файр: локальное время ≥ `UWUWU_LEAD_AUDIT_AT`, сутки не
  отработаны (`cron.lastFireDate`), очередь пуста → промпт аудита в общую
  очередь вечной сессии. Занятая сессия — штатный стирт посреди хода
  (ночная коллизия с диалогом маловероятна). Доставка сводки — механика
  ядра (at-least-once).
- **Тихие сутки**: крон-промпт несёт `allowSilent` — ход без единого
  текстового ответа не доставляет «(пустой ответ)», молчание легитимно;
  оборванный прогон — пометка владельцу (аудит упал, сводки не было).
- Права: деф без ограничений (решение владельца — агент полноценный,
  паритет триажа); дисциплина — методичкой: действия только `task create`
  (Draft) для долга, чужие задачи/статусы не трогает.
- **model из дефа к primary-сессиям не применяется** — демон передаёт
  модель явно (hub.json `model` ?? дефолт профиля) при создании сессии и
  switchModel на каждом ходу; формат с `variant`.

## Проверка (досмерджевый протокол, mock-TG)

Живой прогон против mock-TG и реального локального opencode-сервера — без
реального Telegram и прод-state (см. `triage/README` — механика та же):

```bash
# изолированный рантайм демона
export UWUWU_LEAD_HOME=/tmp/uwuwu-lead-e2e
bun triage/mock-tg.ts --port 8098 --log /tmp/uwuwu-lead-e2e/mock-tg-sent.jsonl &   # mock живёт в triage/
export UWUWU_LEAD_TG_API=http://127.0.0.1:8098
# апдейт владельца снаружи: /start лочит чат (обязательный шаг — до него
# аудит-сводки уходят в лог)
curl -s -X POST http://127.0.0.1:8098/admin/push -H 'content-type: application/json' -d '{
  "update": { "message": { "message_id": 11, "chat": { "id": 42, "type": "private" },
             "from": { "username": "owner", "is_bot": false }, "text": "/start" } } }'
# аудит на ближайшую минуту + ускоренные тайминги
UWUWU_LEAD_AUDIT_AT="$(date -d '+1 minute' +%H:%M)" UWUWU_LEAD_BATCH_MS=2000 \
  UWUWU_LEAD_POLL_SEC=1 UWUWU_LEAD_E2E=1 bun lead/lead.ts
```

Проверки: в логе — «ночной аудит в очередь», ход в вечной сессии `[e2e] 🌙
Lead uwuwu` с моделью `glm-5.3#max`, сводка в `mock-tg-sent.jsonl`
(sendMessage в чат 42); второй файр в те же сутки не повторяется
(`cron.lastFireDate`). Тихий аудит: тихий ход не даёт «(пустой ответ)».
