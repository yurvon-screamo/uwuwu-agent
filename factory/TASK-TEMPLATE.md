# Шаблоны тел фабричных задач

Тело задачи — саб-док доски «Задачи <Proj>» (SiYuan database).
Фабрика тело не парсит: агент читает его сам (`uwuwu-cli task get`), спавн-промпт демона —
короткий (см. `factory-lib.ts::spawnPrompt`). Ниже — шаблоны и правила формата.

## Правила формата (обязательные)

- **Markdown должен переживать round-trip SiYuan**: заголовки `##`, списки, жирный.
  Без HTML и вики-синтаксиса `[[ ]]` — они не переносятся через export/import доков.
  Диаграммы — самодостаточный HTML-блок, вставленный вручную в UI SiYuan (cli-фенсы
  ```html_embed на SiYuan v1 не конвертируются — задача-долг); в markdown-теле диаграмма
  живёт словами/фенсом-заглушкой, а живой блок не переживёт `task body --replace` —
  пересоздание руками (skill `visual-diagrams`).
- **Комменты агентов пишет бот-аккаунт** — демон отличает их от юзерских по автору
  (маркер `🤖` — legacy-фоллбек для старых комментов без автора).

## Шаблон: стандартная задача

```
## Контекст

<что происходит, почему это проблема/потребность; ссылки на доки>

## Что сделать

<желаемый результат — ЧТО, не КАК; критерии приёмки>
```

## Шаблон: spike-задача (исследование)

Для задач, результат которых — вывод и рекомендация, а не фича:

```
## Контекст

<что проверяем и зачем>

## Варианты

<что рассматривали: суть → плюсы/минусы/замеры; сравнение — таблица>

## Вывод

<рекомендация + доказательства: «путь A, потому что …»>

## Границы

<что НЕ исследовано и почему; где вывод не действует>
```

Отчёт агента по spike идёт комментом 🤖 в тело задачи; follow-up задачи на найденные
проблемы заводит владелец доски.
