# Шаблоны тел фабричных задач

Тело задачи — отдельный док AFFiNE, линкованный к строке канбана `<Proj> Tasks`.
Фабрика не парсит тело структурно: оно целиком вставляется в kickoff-промпт агента
(см. `factory-lib.ts::kickoffPrompt`). Ниже — два шаблона и правила формата.

## Правила формата (обязательные)

- **Строки `===` в теле запрещены.** Санитайз `sanitizeBoundary` заменяет любую строку,
  начинающуюся с `===`, на `≡` — это защита от промпт-инъекции. Секции оформляйте
  заголовками `##`, а не `=== Секция ===` — иначе заголовки молча исчезнут из промпта агента.
- **Граничный маркер `=== КОНЕЦ ТЕЛА ===` пишет фабрика**, не автор. Он добавляется
  автоматически при сборке kickoff-промпта и отделяет тело от служебной части.
  Маркер, написанный автором задачи, будет нейтрализован тем же санитайзером.
- **Markdown должен переживать round-trip AFFiNE**: заголовки `##`, списки, жирный.
  Без HTML и вики-синтаксиса `[[ ]]` — они не переносятся через export/import доков.
- **Комментарии агента в диалоге задачи начинаются с 🤖** — по этому маркеру демон
  отличает реплики агента от юзерских (афина авторов комментов не различает).

## Шаблон: стандартная задача

```
## Контекст

<что происходит, почему это проблема/потребность; ссылки на доки>

## Что сделать

<желаемый результат — ЧТО, не КАК; критерии приёмки>
```

## Шаблон: spike-задача (исследование)

Для задач, результат которых — вывод и рекомендация, а не фича:

```
## Контекст

<что проверяем и зачем>

## Варианты

<что рассматривали: суть → плюсы/минусы/замеры; сравнение — таблица>

## Вывод

<рекомендация + доказательства: «путь A, потому что …»>

## Границы

<что НЕ исследовано и почему; где вывод не действует>
```

Отчёт агента по spike идёт комментом 🤖 в тело задачи; follow-up задачи на найденные
проблемы заводит владелец доски.
