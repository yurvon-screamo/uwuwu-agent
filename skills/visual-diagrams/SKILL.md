# Visual Diagrams

Форма следует содержанию. Это не «кубики со стрелками», а полная выразительность веба внутри дока uwuwu.

## Как писать

- **Нод-графы (архитектуры, конвейеры, связи)** → статичный **SVG/inline-HTML** (dagre-раскладка руками или визуальный редактор; JS-движки на SiYuan v1 не исполняются)
- Текстовые блок-схемы/сиквенсы → mermaid (инлайн; SiYuan рендерит mermaid-фенсы нативно)
- Возьми `assets/template-vesper.html` (тема для плоского HTML) — палитра + типографика, макет и фигуры свои под содержание
- Без JS/CDN/анимаций: SiYuan v1 не исполняет JS в html-блоках (интерактив афин-эпохи не переносится)
- Живые примеры в проде: «uwuwu: Стек и архитектура» L0/L1 (статичные HTML-блоки, пары «⁂ diagram:* + html»)

## Два слоя визуала (онтология выбора)

Выбор движка = вопрос «какой слой», не «какая библиотека»:

1. **Визуал в моменте** — объяснить конкретную вещь сейчас: сиквенс в теле задачи, механизм в статье опыта, инцидент в ранбуке. Движки: статичный SVG/inline-HTML (нод-графы), mermaid (сиквенсы/флоу), голый Vesper-HTML (таймлайны/кастом) — всё статично. Не обновляется никогда — устарела вместе с контекстом, так и задумано; порог создания минимальный.
2. **Модель проекта (C4)** — каноническое описание структуры, живёт годами: элемент, связь, deployment-уровень. Только LikeC4: док «Модель (LikeC4)» в папке проекта (источник истины), в Стек-доке — визуализация + линк на модель. Обновление: правка DSL → `likec4 validate`; рендер вью — PNG-экспорт (см. LikeC4-секцию). Стабильные id элементов = линки между вью и доками.

Cytoscape-эмбеды афин-эпохи в Стек-доках мертвы с миграции 04.11 (JS не исполняется) — при ревизии доков заменяются статичным SVG или визуализацией по LikeC4-канону (прецедент: true-washing); новые cytoscape-диаграммы не создавать.

## LikeC4: модель-как-код в вики (канон жив, интерактив-вью мёртв, PNG-рендер жив)

Когда архитектура = **модель** (стабильные id элементов, несколько связанных вью, deployment-уровень, статические линки) — не разовая диаграмма. DSL-исходники живут **в вики** (воркспейс SiYuan).

- **Хранение (канон)**: док `Модель (LikeC4)` в папке проекта; исходники — фенсами ` ```c4 ` (specification/model/views/deployment отдельными секциями). В Стек-доке — визуализация + линк на модель-док. Запрет — на ручные копии и второй источник правки: DSL правят только в вики. Сгенерированный из модели срез (односторонний sync в репу, руками не правится) — не второй источник, а штатный паттерн (ADR-013 true-washing).
- **Живое на SiYuan v1** (live-check 08.11.2026): likec4 CLI (`bun add -g likec4@1.60.0`) работает без браузера — `likec4 validate` и `likec4 format` (проба на модели true-washing: validate валидирует 4 файла, format правит форматирование). Процедура: экспортируй модель-док (`uwuwu-cli read` или `wiki_ops export`), вырежи c4-фенсы в `*.c4`-файлы папки, прогони `likec4 validate`. DSL = источник истины архитектуры.
- **Рендер-вью в доке SiYuan (интерактив) мёртв**: webcomponent (`<likec4-view>` + wc.mjs, React внутри) требует JS — html-блок SiYuan его не исполняет; интерактив LikeC4 (навигация по вью, element-details) недоступен. Старый конвейер `tools/likec4_refresh.py` удалён purge-коммитом d63cdc4 (был написан под афинный wiki_ops). Существующие likec4-эмбеды (Стек-док true-washing) — мёртвые с миграции 04.11.
- **PNG-экспорт жив** (live-check 09.11.2026, спайк 20261108104457-6wsptcd): в папке `*.c4` — `env -u OPENROUTER_API_KEY likec4 export png --dark -o png-out`; playwright (прямая dep likec4) стартует chromium из `~/.cache/ms-playwright`, проба на модели true-washing — 4 вью → 4 валидных PNG за ~40с (dark, до 7028px по ширине). **Триггер тихого провала — AI-ключи в env** (`OPENROUTER_API_KEY`, а также OPENAI/ANTHROPIC/GEMINI/OLLAMA_HOST/MINIMAX): активируется AI-фича preview-сервера → likec4 требует `@tanstack/ai`, не резолвящийся от cwd (голая папка без node_modules) → «Package manager not detected» → `exit(1)` без PNG и без внятной ошибки про playwright. В env без этих ключей — `env -u` не нужен. Диагноз и процедура — опыт-док `cli/LikeC4 CLI & DSL Authoring` (секция «Экспорт PNG»); PNG вставляется в док/задачу как asset-файл.
- **Практика сейчас**: визуализация в Стек-доке — статичный SVG/inline-HTML по мотивам DSL (см. «Как писать»), вставка — html_embed в телах задач или `wiki_ops block-insert-html` в произвольных доках; модель-док — источник истины, синхронизация вью руками.
- Ссылки: ADR-052 uwuwu (html_embed-фенсы, маркер-адресация), опыт-док «AFFiNE embed_html: живые HTML-диаграммы в контуре вики» (секция SiYuan v1).

## Возможности (SiYuan v1, live-check 06.11.2026)

- html-блок SiYuan принимает HTML в потоке дока: inline-styles, SVG, `<div>`-макеты — рендер нативный
- **JS не исполняется** (нет sandbox-iframe афин-эпохи) — диаграммы статичные; анимации/степперы/CDN (unpkg/jsdelivr) — не работают, не закладывай
- афин-доки с `embed_html`-блоками (JS/CDN) при миграции 04.11 потеряли интерактив — существенное дублируется текстом (см. канон «Стек и архитектура»)

## Правила выживания (единственные ограничения)

1. **Без внешних CDN** — док должен рендериться и через годы, всё инлайн
2. **Текст вокруг несёт смысл** — в export/embed диаграмма = плейсхолдер; важное дублируется словами в теле
3. Качество — ui-скилл `architect-ui-ux`: без AI-слопа, типографика, дисциплина

## Вставка и жизненный цикл

Cli-канал — `uwuwu-cli task body` с фенсами ` ```html_embed [имя] ` (SiYuan v1, конвертация реализована):

- **анонимный фенс** — html инлайн в тело (живой HTML-блок в месте фенса);
- **именованный непустой** — пара «маркер-абзац `⁂ diagram:<имя>` + html»: append обновляет диаграмму в доке по маркеру (replace/insert/delete — пустой фенс удаляет), `--replace`/`--replace-section`/create пишут пару как есть;
- живой html-блок с той же смысловой нагрузкой — самодостаточный HTML без пустых строк (пустая строка разрывает html-блок Lute — cli откажет на входе); правка вне тел задач — руками в UI или `tools/wiki_ops.py` block-surgery (программная вставка живого html-блока — `block-insert-html`, маркер-режим `--after-marker` по конвенции `⁂ diagram:<имя>`);
- существующие живые html-блоки тела переживают `--replace`/`--replace-section` (экспорт ядра отдаёт их сырым HTML — round-trip не ломает блок); live-check ядра 3.8.10, 06.11;
- ⚠ SiYuan v1 **не исполняет JS** в html-блоках — диаграммы статичные (SVG/inline-styles), интерактив афин-эпохи (cytoscape/CDN) не переносится;
- LikeC4-фенсы ` ```c4 ` — DSL модель-дока проекта (источник истины для likec4 CLI, см. LikeC4-секцию), не канал вставки диаграмм

Если нужно сослаться на задачу/крон в тексте — резолв `<id>` тот же, что у task get/comment (row-id/префикс/подстрока).
